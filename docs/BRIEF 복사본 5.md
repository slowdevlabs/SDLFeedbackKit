# Country Dataset Specification

## 1. 문서 목적

이 문서는 여러 앱과 서비스에서 공통으로 사용할 수 있는 국가 데이터셋의 구조와 관리 기준을 정의한다.

이 데이터셋은 `Swipe: Flags`를 위해 처음 만들어지지만, 특정 앱에 종속되지 않는다.

`Swipe: Flags`는 이 데이터셋의 첫 번째 사용처이며, 이후 국가 선택, 여행, 시간대, 수도, 통화, 전화번호, 공휴일 등 국가 정보가 필요한 다른 앱에서도 동일한 데이터셋을 재사용할 수 있다.

이 문서의 목적은 다음과 같다.

* 국가 데이터를 하나의 공통 기준으로 관리한다.
* 앱마다 국가명, 코드, 지역 분류를 중복 작성하지 않는다.
* 데이터와 국기 자산의 출처를 일관되게 관리한다.
* 여러 플랫폼에서 사용할 수 있는 단순한 JSON 구조를 제공한다.
* 데이터 변경과 배포 버전을 추적할 수 있도록 한다.
* 공통 데이터와 앱 전용 설정을 명확히 분리한다.

---

## 2. 기본 원칙

### 2.1 앱 독립성

공통 데이터셋에는 특정 앱의 기능이나 운영 상태를 저장하지 않는다.

다음과 같은 정보는 공통 데이터셋에 포함하지 않는다.

* 퀴즈 난이도
* 문제 출제 빈도
* 오답 후보
* 게임 스테이지
* 앱 내 잠금 여부
* `Swipe: Flags` MVP 포함 여부
* 사용자 정답률
* 앱별 정렬 순서
* 앱별 유료 또는 무료 상태

이러한 정보는 각 앱의 별도 설정 파일에서 관리한다.

예:

```text
country-dataset
└── 국가와 국기 자체에 대한 공통 정보

SwipeFlags
└── 출제 대상, 난이도, 문제 구성 등 게임 전용 정보
```

---

### 2.2 단순한 JSON 기반

초기 데이터셋은 데이터베이스나 API 서버 없이 JSON 파일과 SVG 자산으로 관리한다.

기본 구성은 다음과 같다.

```text
JSON 데이터
+
SVG 국기 자산
+
버전 정보
+
출처와 라이선스 문서
```

JSON은 다음 이유로 초기 배포 형식으로 사용한다.

* 사람이 직접 읽고 검토할 수 있다.
* Git에서 변경 이력을 확인하기 쉽다.
* iOS, macOS, Android, 웹 등에서 공통으로 사용할 수 있다.
* 앱 번들에 포함해 오프라인으로 사용할 수 있다.
* 필요할 경우 원격 URL을 통해 그대로 배포할 수 있다.
* 현재 데이터 규모에는 별도 데이터베이스가 필요하지 않다.

데이터베이스와 API는 CMS, 실시간 편집, 사용자별 데이터, 대규모 검색 등의 필요가 실제로 생겼을 때 검토한다.

---

### 2.3 하나의 기준 원본

국가 데이터의 기준 원본은 `country-dataset` 저장소다.

다른 앱에서 복사한 데이터가 있더라도 직접 수정하지 않는다.

데이터 수정 흐름은 다음을 따른다.

```text
country-dataset 수정
→ 검증
→ 데이터셋 버전 업데이트
→ 릴리스
→ 각 앱에서 새 버전 반영
```

앱에서 발견된 오류도 우선 공통 데이터셋에서 수정한 뒤 앱에 반영한다.

---

### 2.4 필요한 데이터부터 확장

처음부터 가능한 모든 국가 정보를 포함하지 않는다.

초기 버전에서는 여러 앱에서 공통 기준으로 사용할 가능성이 높고, `Swipe: Flags`에 직접 필요한 정보만 포함한다.

새로운 필드는 다음 조건 중 하나를 만족할 때 추가한다.

* 두 개 이상의 앱에서 사용할 가능성이 높다.
* 국가를 식별하거나 분류하는 핵심 정보다.
* 기존 필드만으로 표현할 수 없다.
* 신뢰할 수 있는 출처와 관리 기준이 있다.
* 지속적으로 유지할 수 있다.

단순히 미래에 사용할 수도 있다는 이유만으로 필드를 추가하지 않는다.

---

## 3. 초기 데이터셋 범위

초기 데이터셋은 다음 정보를 관리한다.

* 내부 국가 ID
* ISO 3166-1 Alpha-2 코드
* ISO 3166-1 Alpha-3 코드
* ISO 3166-1 숫자 코드
* 영어, 한국어, 스페인어 국가명
* 대륙
* 하위 지역
* 국가 또는 지역의 상태
* 활성 여부
* 국기 SVG 자산 경로

초기 데이터셋에는 다음 정보를 포함하지 않는다.

* 인구
* 면적
* GDP
* 국가별 설명
* 위도와 경도
* 수도
* 공식 언어
* 통화
* 전화 국가번호
* 시간대
* 공휴일
* 국가별 도메인
* 운전 방향
* 측정 단위
* 앱스토어 국가 코드
* 국기 색상 분석
* 국기 유사도
* 역사적 국가와 과거 국기

위 정보는 실제 사용처가 생길 때 별도 필드 또는 모듈로 추가할 수 있다.

---

## 4. 포함 대상

### 4.1 전체 데이터셋

공통 데이터셋은 ISO 3166-1에 등록된 국가와 지역을 기본 대상으로 한다.

전체 데이터에는 다음 유형이 포함될 수 있다.

* 주권 국가
* 속령 및 해외 영토
* 특별 행정 지역
* 기타 ISO 등록 지역

`Swipe: Flags`에서 초기 사용하지 않는 항목도 공통 데이터셋에는 준비할 수 있다.

즉, 데이터셋의 전체 범위와 개별 앱의 공개 범위는 서로 다를 수 있다.

---

### 4.2 Swipe: Flags MVP

`Swipe: Flags` MVP는 공통 데이터셋 중 195개 주권 국가를 우선 사용한다.

그러나 `195개`라는 기준은 게임의 초기 출제 범위이지, 공통 데이터셋의 전체 범위를 의미하지 않는다.

공통 데이터셋에 포함된 모든 항목은 향후 앱 설정 변경을 통해 사용할 수 있어야 한다.

`Swipe: Flags`의 출제 대상 목록은 앱 저장소의 별도 파일에서 관리한다.

예:

```text
SwipeFlags/GameData/quiz-country-pool.json
```

---

### 4.3 분쟁 지역

분쟁 지역이나 승인 상태가 복잡한 항목은 데이터에 포함할 수 있지만, 단정적인 정치적 해석을 데이터셋이 직접 제공하지 않는다.

필요한 경우 상태 필드로만 구분하고, 해당 분류 기준과 출처를 문서에 기록한다.

분쟁 지역을 `Swipe: Flags`에 출제할지는 앱 전용 정책에서 별도로 결정한다.

---

### 4.4 역사적 국가와 과거 국기

역사적 국가와 과거 국기는 초기 버전에서 제외한다.

향후 필요할 경우 현재 국가 데이터와 섞지 않고 별도 데이터 파일 또는 모듈로 분리한다.

예:

```text
data/historical-countries.json
assets/flags/historical/
```

---

## 6. 파일별 역할

### 6.1 `manifest.json`

데이터셋 전체의 버전, 지원 언어, 파일 경로, 항목 수를 기록한다.

사용자와 앱은 이 파일을 통해 현재 데이터셋의 상태를 확인할 수 있다.

예:

```json
{
  "dataset": "country-dataset",
  "datasetVersion": "0.1.0",
  "schemaVersion": "0.1.0",
  "releasedAt": null,
  "defaultLanguage": "en",
  "supportedLanguages": [
    "en",
    "ko",
    "es"
  ],
  "files": {
    "countries": "data/countries.json",
    "regions": "data/regions.json",
    "flags": "assets/flags/svg"
  },
  "counts": {
    "entries": 0,
    "sovereignStates": 0,
    "flagAssets": 0
  }
}
```

개발 중에는 `releasedAt`을 `null`로 둘 수 있다.

공개 릴리스에서는 ISO 8601 형식의 날짜를 기록한다.

예:

```json
"releasedAt": "2026-08-15"
```

---

### 6.2 `data/countries.json`

모든 국가와 지역 항목의 핵심 정보를 관리한다.

이 파일이 데이터셋의 중심이다.

예:

```json
{
  "datasetVersion": "0.1.0",
  "countries": [
    {
      "id": "kr",
      "iso2": "KR",
      "iso3": "KOR",
      "numericCode": "410",
      "names": {
        "en": "South Korea",
        "ko": "대한민국",
        "es": "Corea del Sur"
      },
      "regionId": "asia",
      "subregionId": "eastern-asia",
      "status": "sovereign-state",
      "flag": {
        "assetId": "flag-kr",
        "svg": "assets/flags/svg/kr.svg"
      },
      "isActive": true
    }
  ]
}
```

---

### 6.3 `data/regions.json`

대륙과 하위 지역의 ID 및 다국어 표시명을 관리한다.

국가마다 대륙 이름을 반복 입력하지 않고 `regionId`와 `subregionId`로 참조한다.

예:

```json
{
  "datasetVersion": "0.1.0",
  "regions": [
    {
      "id": "asia",
      "names": {
        "en": "Asia",
        "ko": "아시아",
        "es": "Asia"
      }
    }
  ],
  "subregions": [
    {
      "id": "eastern-asia",
      "regionId": "asia",
      "names": {
        "en": "Eastern Asia",
        "ko": "동아시아",
        "es": "Asia Oriental"
      }
    }
  ]
}
```

지역 분류는 하나의 기준을 선택해 일관되게 사용한다.

초기에는 UN M49 지역 분류를 우선 검토한다.

---

### 6.4 `assets/flags/svg/`

현재 국기 SVG 파일을 저장한다.

국기 파일명은 ISO Alpha-2 코드를 소문자로 변환해 사용한다.

예:

```text
KR → kr.svg
JP → jp.svg
US → us.svg
```

---

### 6.5 `SOURCES.md`

국가 코드, 국가명, 지역 분류, 번역, 국기 자산의 출처를 기록한다.

출처는 데이터 작성과 동시에 기록한다.

최소 기록 항목은 다음과 같다.

* 출처명
* 사용한 정보
* 원본 URL 또는 식별 정보
* 라이선스
* 확인 날짜
* 적용한 수정 또는 정규화
* 보조 검증 출처

국기 SVG의 출처와 데이터의 출처는 별도로 기록할 수 있다.

---

### 6.6 `schemas/`

JSON 파일의 구조를 검증하는 JSON Schema를 저장한다.

초기 스키마는 모든 세부 오류를 검사하기보다 다음과 같은 기본 오류를 차단하는 데 집중한다.

* 필수 필드 누락
* ISO 코드 길이 오류
* 허용되지 않은 상태 값
* 지원 언어 누락
* 잘못된 값 형식

중복 ID, 실제 파일 존재 여부, 미사용 자산 등은 별도 검증 스크립트에서 검사한다.

---

### 6.7 `scripts/validate.py`

데이터와 자산을 자동으로 검사한다.

초기 검증 범위는 다음과 같다.

* JSON 문법 오류
* 필수 필드 누락
* 중복 내부 ID
* 중복 ISO2 코드
* 중복 ISO3 코드
* 잘못된 숫자 코드 형식
* 존재하지 않는 `regionId`
* 존재하지 않는 `subregionId`
* 하위 지역과 대륙 연결 불일치
* 영어, 한국어, 스페인어 국가명 누락
* 존재하지 않는 국기 SVG 경로
* 연결되지 않은 SVG 파일
* 잘못된 SVG 파일명
* `manifest.json`의 개수 불일치

---

### 6.8 `dist/`

외부 사용자가 실제로 사용하는 배포 파일을 저장한다.

관리용 원본과 배포용 파일을 구분할 필요가 생긴 시점부터 사용한다.

초기에는 원본 구조가 단순하므로 `dist` 없이 시작할 수 있다.

공개 릴리스에서는 다음처럼 구성할 수 있다.

```text
dist/
├── manifest.json
├── countries.json
├── regions.json
└── flags/
    └── svg/
```

## 7. 국가 데이터 필드 정의

### 7.1 `id`

데이터셋 내부에서 사용하는 고유 식별자다.

예:

```json
"id": "kr"
```

초기에는 ISO Alpha-2 코드의 소문자 값을 사용한다.

규칙:

* 소문자 영문 두 글자
* ISO Alpha-2와 동일한 값을 소문자로 변환
* 데이터 연결 기준으로 사용
* 표시명으로 사용하지 않음
* 기존 ID는 특별한 이유 없이 변경하지 않음

예:

```text
KR → kr
JP → jp
US → us
```

ISO 코드가 변경되는 특수한 상황에서는 데이터 이전 정책을 별도로 검토한다.

---

### 7.2 `iso2`

ISO 3166-1 Alpha-2 코드다.

예:

```json
"iso2": "KR"
```

규칙:

* 대문자 영문 두 글자
* 필수
* 데이터셋 내 중복 불가

---

### 7.3 `iso3`

ISO 3166-1 Alpha-3 코드다.

예:

```json
"iso3": "KOR"
```

규칙:

* 대문자 영문 세 글자
* 필수
* 데이터셋 내 중복 불가

---

### 7.4 `numericCode`

ISO 3166-1 숫자 코드다.

예:

```json
"numericCode": "410"
```

규칙:

* 문자열로 저장
* 숫자 세 자리 형식
* 앞의 0을 유지
* 필수 여부는 최종 소스 검증 후 확정
* 값이 없는 경우 임의 값을 만들지 않음

숫자형이 아니라 문자열로 저장하는 이유는 `008`과 같은 코드의 앞자리 0을 보존하기 위해서다.

---

### 7.5 `names`

사용자에게 표시할 다국어 국가명이다.

예:

```json
"names": {
  "en": "South Korea",
  "ko": "대한민국",
  "es": "Corea del Sur"
}
```

초기 필수 언어:

```text
en
ko
es
```

규칙:

* 영어, 한국어, 스페인어 모두 필수
* 빈 문자열 금지
* 내부 식별에는 사용하지 않음
* 앱 화면에서 일반적으로 사용하는 국가명 기준
* 지나치게 긴 공식 국호보다 일반 사용자에게 익숙한 표기를 우선 검토
* 공식명과 일반명이 모두 필요해질 경우 별도 필드 추가를 검토

초기 버전에서는 `officialNames`, `shortNames`, `aliases`를 추가하지 않는다.

---

### 7.6 `regionId`

대륙 또는 상위 지역 ID다.

예:

```json
"regionId": "asia"
```

값은 반드시 `regions.json`의 `regions` 항목에 존재해야 한다.

초기 예상 값:

```text
africa
americas
asia
europe
oceania
```

실제 값과 명칭은 선택한 지역 분류 기준에 맞춰 확정한다.

---

### 7.7 `subregionId`

하위 지역 ID다.

예:

```json
"subregionId": "eastern-asia"
```

값은 반드시 `regions.json`의 `subregions` 항목에 존재해야 한다.

해당 하위 지역의 `regionId`와 국가의 `regionId`가 일치해야 한다.

값을 확정할 수 없는 경우 임의 분류하지 않는다.

초기 데이터 완성 과정에서 필수 여부를 검토하되, 가능한 모든 항목에 제공하는 것을 원칙으로 한다.

---

### 7.8 `status`

해당 항목의 기본 상태 또는 유형을 나타낸다.

초기 허용 값:

```text
sovereign-state
dependent-territory
special-area
disputed
```

#### `sovereign-state`

일반적인 주권 국가로 분류되는 항목이다.

#### `dependent-territory`

다른 국가와 헌법적 또는 행정적 관계를 가진 속령이나 해외 영토다.

#### `special-area`

특별행정구 또는 일반적인 주권 국가와 속령 분류만으로 설명하기 어려운 특수 지역이다.

#### `disputed`

국제적 승인이나 영유권 상태가 복잡한 항목이다.

상태 값은 앱의 정치적 판단이나 설명문을 대신하지 않는다.

분류가 논쟁적일 수 있는 항목은 `SOURCES.md` 또는 별도 문서에 기준을 기록한다.

---

### 7.9 `flag`

국기 자산 정보를 저장한다.

초기 구조:

```json
"flag": {
  "assetId": "flag-kr",
  "svg": "assets/flags/svg/kr.svg"
}
```

#### `assetId`

국기 자산의 내부 식별자다.

규칙:

```text
flag-{countryId}
```

예:

```text
flag-kr
flag-jp
flag-us
```

#### `svg`

저장소 루트를 기준으로 한 국기 SVG 상대 경로다.

예:

```text
assets/flags/svg/kr.svg
```

초기에는 SVG 경로만 관리한다.

PNG, WebP, 소형 버전 등이 실제로 필요해질 경우 `flag` 객체에 필드를 추가하거나 별도 자산 매니페스트로 분리한다.

---

### 7.10 `isActive`

현재 데이터셋에서 사용 가능한 항목인지 나타낸다.

예:

```json
"isActive": true
```

이 필드는 특정 앱의 공개 여부를 의미하지 않는다.

사용 예:

* 데이터가 검증 완료된 항목
* 현재 데이터셋에서 제공 중인 항목
* 폐기되었거나 교체된 항목의 비활성화

규칙:

* 정상 제공 항목은 `true`
* 검증 중인 항목은 공개 데이터에 포함하지 않는 것을 우선
* 과거 ID 보존 등의 이유가 있을 때만 `false` 사용
* `Swipe: Flags` 출제 여부와 연결하지 않음

---

## 8. 다국어 정책

### 8.1 초기 지원 언어

초기 데이터셋은 다음 언어를 지원한다.

```text
en — English
ko — Korean
es — Spanish
```

이는 현재 주요 앱의 기본 지원 언어와 일치한다.

---

### 8.2 언어 코드

언어 키는 BCP 47 또는 ISO 언어 코드 관례를 참고하되, 초기에는 단순한 2자리 언어 코드를 사용한다.

예:

```json
{
  "en": "Japan",
  "ko": "일본",
  "es": "Japón"
}
```

지역별 표기가 실제로 필요해질 경우 다음과 같은 확장을 검토할 수 있다.

```text
pt-BR
zh-Hans
zh-Hant
```

초기에는 지역별 언어 코드를 사용하지 않는다.

---

### 8.3 영어 폴백

앱에서 요청한 언어가 없을 경우 영어 값을 폴백으로 사용할 수 있다.

권장 처리 순서:

```text
요청 언어
→ 영어
→ 내부 ID
```

그러나 초기 필수 언어 세 개는 모두 데이터에 존재해야 하므로 폴백은 예외 상황을 위한 안전장치다.

---

### 8.4 번역 기준

국가명 번역은 자동 번역 결과만으로 확정하지 않는다.

우선순위는 다음과 같다.

1. 공식 또는 공신력 있는 표기
2. 해당 언어권에서 일반적으로 사용하는 표기
3. 주요 지도 또는 국제 서비스에서 일관되게 사용되는 표기
4. 별도 검증된 번역

표기 차이가 있는 경우 출처와 선택 이유를 기록한다.

---

## 9. 지역 분류 정책

국가의 대륙과 하위 지역은 하나의 공통 분류 기준을 따른다.

초기 기준으로 UN M49 지역 분류를 우선 검토한다.

분류 기준은 데이터 작성 전에 최종 확정하고 `SOURCES.md`에 기록한다.

임의로 앱마다 다른 지역 분류를 공통 데이터에 섞지 않는다.

앱이 별도의 게임 지역 구분을 필요로 할 경우 앱 전용 설정에서 변환한다.

예:

```text
공통 데이터
→ Northern America

앱 전용 표시
→ North America
```

공통 데이터의 원본 분류와 앱의 사용자 표시 분류는 다를 수 있다.

---

## 10. 국기 자산 정책

### 10.1 파일 형식

초기 기본 국기 자산은 SVG로 제공한다.

SVG를 사용하는 이유:

* 다양한 화면 크기에서 선명하게 표시할 수 있다.
* 웹과 앱에서 재사용하기 쉽다.
* 원본 비율을 유지하기 쉽다.
* PNG 파생 파일을 나중에 생성할 수 있다.

---

### 10.2 파일명

국기 SVG 파일명은 ISO Alpha-2 코드의 소문자를 사용한다.

```text
kr.svg
jp.svg
us.svg
```

국가명이나 내부 표시명을 파일명으로 사용하지 않는다.

---

### 10.3 비율

각 국기의 공식 비율을 유지한다.

모든 SVG를 동일한 가로세로 비율로 강제 변형하지 않는다.

앱은 표시 영역에서 다음 방식 중 하나를 사용해야 한다.

* 원본 비율 유지
* `aspectFit`
* 정해진 프레임 안에서 여백 허용

국기를 프레임에 맞추기 위해 늘이거나 찌그러뜨리지 않는다.

---

### 10.4 SVG 정규화

국기 SVG는 배포 전에 다음을 확인한다.

* 올바르게 렌더링되는지
* 불필요한 편집기 메타데이터가 과도하게 포함되지 않았는지
* 외부 리소스에 의존하지 않는지
* 스크립트나 위험한 외부 참조가 없는지
* `viewBox`가 존재하는지
* 원본 색상이 유지되는지
* 배경이 의도와 다르게 추가되지 않았는지
* 파일명이 ISO 코드 규칙과 일치하는지

파일 용량 최적화는 시각적 정확성을 훼손하지 않는 범위에서만 수행한다.

---

### 10.5 국기 출처

각 국기 자산의 출처와 라이선스를 기록한다.

전체 국기가 동일 출처인 경우 `SOURCES.md`에서 묶어서 기록할 수 있다.

출처가 서로 다른 경우 자산별 기록이 필요할 수 있다.

국기 디자인 자체의 공공성 여부와 SVG 파일 제작물의 라이선스는 구분해서 확인한다.

특정 출처의 SVG를 그대로 복사해 사용할 경우 해당 출처의 라이선스 조건을 따른다.

---

### 10.6 파생 자산

초기에는 SVG만 제공한다.

향후 필요할 경우 다음 자산을 자동 생성할 수 있다.

```text
PNG 128
PNG 256
PNG 512
WebP
watchOS용 소형 래스터 이미지
```

파생 자산은 원본 SVG에서 생성하며, 수동으로 별도 수정본을 만들지 않는 것을 원칙으로 한다.

---

## 11. 공통 데이터와 앱 전용 데이터의 분리

### 11.1 공통 데이터셋에 포함되는 정보

예:

```text
국가 ID
ISO 코드
국가명
대륙
하위 지역
국가 상태
국기 자산
```

---

### 11.2 Swipe: Flags에 포함되는 정보

예:

```text
MVP 출제 대상
국가별 난이도
문제 출제 가중치
오답 후보 구성
진행 단계
잠금 여부
게임 내 그룹
정답 인정 별칭
```

예시 앱 전용 파일:

```json
{
  "datasetVersion": "0.1.0",
  "poolId": "mvp",
  "countryIds": [
    "kr",
    "jp",
    "us"
  ]
}
```

이 파일은 `country-dataset`에 포함하지 않고 `SwipeFlags` 저장소에서 관리한다.

---

### 11.3 다른 앱의 사용

다른 앱도 공통 데이터셋의 필드를 그대로 사용하고, 앱별 의미는 자체 설정으로 분리한다.

예:

```text
World Capitals
→ countryId와 별도 수도 데이터 연결

World Timezones
→ countryId와 별도 시간대 데이터 연결

Travel App
→ countryId와 여행 정보 연결
```

공통 데이터셋의 `countryId`를 앱 간 연결 키로 사용한다.

---

## 12. 데이터 작성 절차

### 12.1 구조 검증용 예시 데이터

전체 항목을 입력하기 전에 성격이 다른 소수 항목으로 구조를 검증한다.

권장 초기 예시:

* 대한민국
* 미국
* 프랑스
* 홍콩
* 푸에르토리코

이를 통해 다음 유형을 확인할 수 있다.

* 일반 주권 국가
* 다국어 표기 차이
* 특별 행정 지역
* 속령
* 지역 분류 차이
* 국기 연결 방식

구조가 확정된 이후 전체 데이터를 작성한다.

---

### 12.2 지역별 작성

전체 항목은 지역별로 나누어 작성한다.

권장 순서:

1. Asia
2. Europe
3. Africa
4. Americas
5. Oceania
6. Dependencies and special areas

각 지역 작업은 다음 순서로 진행한다.

```text
ISO 코드 입력
→ 국가명 입력
→ 지역 연결
→ 상태 분류
→ 국기 경로 연결
→ 출처 기록
→ 자동 검증
→ 수동 검수
```

---

### 12.3 자동 생성과 수동 검수

공개 데이터 소스에서 초기 JSON을 자동 생성할 수 있다.

그러나 자동 생성 결과를 그대로 릴리스하지 않는다.

최종 공개 전 다음 항목은 수동 검수한다.

* 국가명
* 한국어와 스페인어 번역
* 지역 분류
* 상태 분류
* 국기 연결
* 파일 누락
* 출처와 라이선스

---

## 13. 검증 기준

데이터 릴리스 전에 최소한 다음 검증을 통과해야 한다.

### 13.1 구조 검증

* JSON 문법이 유효해야 한다.
* 스키마 필수 필드를 모두 가져야 한다.
* 허용되지 않은 필드 형식이 없어야 한다.
* 지원 언어 이름이 모두 존재해야 한다.

---

### 13.2 고유성 검증

* `id` 중복 금지
* `iso2` 중복 금지
* `iso3` 중복 금지
* `numericCode` 중복 여부 확인
* `flag.assetId` 중복 금지

---

### 13.3 참조 검증

* 모든 `regionId`가 존재해야 한다.
* 모든 `subregionId`가 존재해야 한다.
* 하위 지역의 상위 지역이 국가의 `regionId`와 일치해야 한다.
* 모든 국기 경로에 실제 파일이 존재해야 한다.
* 모든 SVG 파일이 하나 이상의 데이터 항목과 연결되어야 한다.

---

### 13.4 내용 검증

* 국가명에 불필요한 앞뒤 공백이 없어야 한다.
* ISO 코드는 올바른 대소문자를 사용해야 한다.
* 숫자 코드는 세 자리 문자열이어야 한다.
* 국가 상태는 허용 값 중 하나여야 한다.
* 국기 파일은 정상적으로 렌더링되어야 한다.
* `manifest.json`의 개수가 실제 데이터와 일치해야 한다.

---

## 14. 버전 정책

데이터셋 버전과 스키마 버전을 분리한다.

### 14.1 `datasetVersion`

데이터 내용의 버전이다.

다음 변경 시 증가한다.

* 국가명 수정
* 번역 수정
* 지역 분류 수정
* 상태 수정
* 새 항목 추가
* 항목 비활성화
* 국기 자산 교체
* 자산 오류 수정

예:

```text
0.1.0
0.1.1
0.2.0
1.0.0
```

---

### 14.2 `schemaVersion`

JSON 구조의 버전이다.

다음 변경 시 증가한다.

* 새 필드 추가
* 필드 이름 변경
* 필드 형식 변경
* 객체 구조 변경
* 기존 필드 제거
* 필수 여부 변경

예:

```text
0.1.0
0.2.0
1.0.0
2.0.0
```

---

### 14.3 버전 증가 기준

#### Patch

기존 구조와 호환되는 작은 데이터 수정이다.

예:

```text
오탈자 수정
번역 수정
잘못된 SVG 교체
```

```text
0.1.0 → 0.1.1
```

#### Minor

기존 구조를 크게 깨지 않으면서 데이터나 선택 필드를 확장한다.

예:

```text
새 지역 항목 추가
새로운 선택 필드 추가
지원 언어 추가
```

```text
0.1.1 → 0.2.0
```

#### Major

기존 사용자 코드의 수정이 필요할 수 있는 변경이다.

예:

```text
필드 이름 변경
기존 필드 제거
JSON 최상위 구조 변경
ID 정책 변경
```

```text
1.3.0 → 2.0.0
```

---

### 14.4 초기 버전

첫 개발 버전은 `0.1.0`으로 시작한다.

전체 데이터, 국기, 출처, 검증, 사용 문서가 안정화된 후 `1.0.0`을 릴리스한다.

`1.0.0` 이전에는 스키마가 변경될 수 있음을 README에 안내한다.

---

## 15. 릴리스 정책

### 15.1 공개 릴리스 포함 파일

공개 ZIP에는 일반 사용자가 필요한 파일만 포함한다.

예:

```text
country-dataset-v0.1.0/
├── README.md
├── LICENSE
├── SOURCES.md
├── manifest.json
├── countries.json
├── regions.json
└── flags/
    └── svg/
```

관리용 스크립트와 내부 문서는 저장소에는 유지하되, 배포 ZIP에서는 제외할 수 있다.

---

### 15.2 버전 고정

외부 사용자와 앱은 가능하면 명시적인 데이터셋 버전을 사용한다.

권장:

```text
country-dataset v1.0.0
```

원격 배포 시 권장:

```text
/country-dataset/v1.0.0/countries.json
```

다음과 같은 `latest` 경로는 테스트와 미리보기 용도로만 사용한다.

```text
/country-dataset/latest/countries.json
```

앱이 `latest`를 직접 사용하면 예기치 않은 데이터 변경으로 동작이 바뀔 수 있다.

---

### 15.3 변경 기록

모든 공개 릴리스는 `CHANGELOG.md`에 변경 내용을 기록한다.

예:

```markdown
## 0.1.1

- Corrected Korean name for one country.
- Replaced malformed SVG asset.
- Fixed region mapping for one territory.
```

## 16. 사용 방식

### 16.1 앱 번들 포함

앱이 JSON과 SVG를 직접 번들에 포함한다.

장점:

* 오프라인 사용 가능
* 서버 장애 영향 없음
* 버전 고정 가능
* 앱 출시 전 검증 가능

`Swipe: Flags` 초기 버전은 이 방식을 기본으로 한다.

---

### 16.2 원격 배포

데이터셋은 나중에 GitHub Release, GitHub Pages, Cloudflare Pages 또는 R2에서 원격 제공할 수 있다.

원격 사용 시 앱은 다음 원칙을 따른다.

```text
번들 기본 데이터
+
원격 manifest 버전 확인
+
새 버전 다운로드
+
로컬 캐시
+
실패 시 번들 데이터 폴백
```

원격 배포 기능은 데이터셋 v1 초기 필수 범위가 아니다.

---

### 16.3 패키지 매니저

Swift Package Manager, npm, Python 패키지 등의 배포는 초기 범위에서 제외한다.

반복적인 설치 수요와 사용자 요청이 확인되면 별도 패키지를 제공할 수 있다.

JSON과 SVG 원본 구조는 특정 패키지 매니저에 종속되지 않아야 한다.

---

## 17. 라이선스 정책

데이터셋은 다음 항목의 라이선스를 구분해서 관리한다.

1. 저장소의 문서와 검증 스크립트
2. 직접 정리한 JSON 데이터
3. 외부 출처를 기반으로 한 데이터
4. 국기 SVG 자산

저장소 전체에 하나의 라이선스를 선언하더라도, 외부 자산에 별도 라이선스가 적용될 수 있다.

README와 `SOURCES.md`에서 이 차이를 명확히 안내한다.

라이선스가 확정되지 않은 자산은 공개 릴리스에 포함하지 않는다.

---

## 18. 변경 및 기여 원칙

외부 사용자는 다음 오류를 제보할 수 있다.

* 국가 코드 오류
* 번역 오류
* 지역 분류 오류
* 상태 분류 오류
* 국기 파일 오류
* SVG 렌더링 문제
* 누락된 항목
* 잘못된 출처 정보

변경 제안에는 가능하면 확인 가능한 출처를 첨부해야 한다.

외부 Pull Request는 자동으로 신뢰하지 않고 다음을 확인한 뒤 병합한다.

* 데이터 출처
* 라이선스
* 기존 스키마 호환성
* 다른 데이터와의 일관성
* 자동 검증 결과
* 시각적 자산 검수

## 19. 초기 구현 범위

### Milestone 1 — Foundation

작성 대상:

```text
docs/DATASET_SPEC.md
manifest.json
data/regions.json
data/countries.json 예시 항목
SOURCES.md 초안
```

완료 기준:

```text
새로운 국가 항목을 어떤 규칙으로 추가해야 하는지 명확하다.
```

---

### Milestone 2 — Core Data

작성 대상:

```text
전체 countries.json
전체 regions.json
영어, 한국어, 스페인어 국가명
ISO 코드
지역 연결
상태 분류
```

완료 기준:

```text
대상 국가와 지역이 중복 없이 존재한다.
```

---

### Milestone 3 — Flag Assets

작성 대상:

```text
assets/flags/svg/
국가와 SVG 연결
국기 출처와 라이선스 기록
```

완료 기준:

```text
모든 활성 항목에 정상 렌더링되는 SVG가 연결되어 있다.
```

---

### Milestone 4 — Validation

작성 대상:

```text
schemas/countries.schema.json
schemas/regions.schema.json
scripts/validate.py
```

완료 기준:

```text
중복, 누락, 잘못된 참조와 자산 경로를 자동으로 검사할 수 있다.
```

---

### Milestone 5 — Distribution

작성 대상:

```text
README.md
LICENSE
CHANGELOG.md
dist/
Swift 사용 예제
JavaScript 사용 예제
GitHub Release
```

완료 기준:

```text
외부 사용자가 README만 보고 데이터와 국기를 사용할 수 있다.
```

---

### Milestone 6 — Swipe: Flags Integration

`Swipe: Flags` 저장소에서 별도로 작성한다.

```text
quiz-country-pool.json
Country Codable 모델
데이터셋 로더
국기 자산 로더
앱에서 사용하는 데이터셋 버전 기록
```

완료 기준:

```text
Swipe: Flags가 자체 중복 국가 데이터 없이 공통 데이터셋을 사용한다.
```

현재 초기 방향은 다음과 같다.

```text
프로젝트 이름:
Country Dataset

저장소 이름:
country-dataset

로컬 위치:
slowDev/GitHub/country-dataset

기본 형식:
JSON + SVG

초기 지원 언어:
English, Korean, Spanish

초기 배포 방식:
GitHub 저장소 및 버전별 ZIP Release

초기 앱 사용 방식:
앱 번들에 데이터와 자산 포함

첫 번째 사용 앱:
Swipe: Flags

초기 앱 출제 범위:
195개 주권 국가

전체 데이터셋 범위:
ISO 3166-1 국가 및 지역을 기준으로 확장
```

## 21. 보류 사항

다음 항목은 실제 데이터 작성과 출처 검토 과정에서 확정한다.

* 최종 국기 SVG 출처
* JSON 데이터 라이선스
* 국기 자산 라이선스
* 지역 분류의 최종 기준
* `status` 값별 세부 판정 기준
* 숫자 코드 필수 여부
* 하위 지역 필수 여부
* 전체 공개 항목 수
* 최초 공개 릴리스 범위
* 원격 배포 URL
* `dist` 자동 생성 방식

보류 사항이 확정되기 전까지 임시 값을 공식 릴리스에 포함하지 않는다.

## 22. 완료 정의

Country Dataset v1.0은 다음 조건을 모두 만족할 때 완료된 것으로 본다.

* 대상 국가와 지역 데이터가 모두 존재한다.
* 모든 필수 필드가 작성되어 있다.
* 영어, 한국어, 스페인어 국가명이 검수되었다.
* 지역과 하위 지역 연결이 검증되었다.
* 모든 활성 항목에 국기 SVG가 연결되어 있다.
* 모든 데이터와 자산의 출처가 기록되어 있다.
* 공개 사용이 가능한 라이선스가 확인되었다.
* 자동 검증 스크립트를 통과한다.
* README에 Swift와 JavaScript 사용법이 제공된다.
* 버전별 배포 ZIP을 생성할 수 있다.
* `Swipe: Flags`에서 공통 데이터셋을 정상적으로 읽고 사용할 수 있다.

이 조건을 충족하기 전까지 데이터셋은 `0.x` 버전으로 유지한다.
